El Orden Obligatorio de las Cláusulas en SQL

Si cambias este orden frente al profesor, SQL lanzará un error de sintaxis. Haz clic en cada bloque para ver ejemplos de tus talleres.

⚠️ ¡Memoriza esta secuencia!
SELECT s.nombre AS sucursal, COUNT(e.id_empleado) AS total_emp
FROM sucursales s
LEFT JOIN empleados e ON s.id_sucursal = e.id_sucursal
WHERE e.salario > 2000000
GROUP BY s.nombre
HAVING COUNT(e.id_empleado) >= 1
ORDER BY total_emp DESC;
1 SELECT (¿Qué columnas o cálculos quieres ver?)

Aquí escribes las columnas que pidió el profesor separadas por comas. Puedes usar AS para ponerle un nombre bonito a la columna (alias), o usar funciones como COUNT(), SUM(), AVG().

Tip vital: Si usas una función como COUNT(...) junto con una columna normal como s.nombre, ¡estás obligado a poner GROUP BY s.nombre más abajo!
Fundamento Esencial Clasificación de Sentencias SQL

DDL vs. DML de Escritura vs. DQL (Mapeado a bancodb)

Distingue el rol exacto de cada familia de comandos evaluadas por el profesor en el Laboratorio Final:

1. DDL (Definición) Estructura / Catálogo

Define contenedores y restricciones

Modifica el catálogo de la BD: crea o altera bases de datos, tablas, tipos, llaves primarias (PK) y foráneas (FK).

// Comandos: CREATE, ALTER, DROP
CREATE DATABASE bancodb;
CREATE TABLE sucursales (
id_sucursal SERIAL PRIMARY KEY,
nombre VARCHAR(100) NOT NULL
);
ALTER TABLE prestamos ADD estado VARCHAR(20);
Regla clave: No manipula filas individuales, solo el plano o molde de almacenamiento.
2. DML (Manipulación) Datos / Filas

Inserta, actualiza o borra registros

Alimenta y mantiene los registros vivos respetando las restricciones de integridad referencial.

// Comandos: INSERT, UPDATE, DELETE
INSERT INTO sucursales(nombre, ciudad)
VALUES ('Sucursal Centro', 'Bogotá');
UPDATE cuentas
SET saldo = saldo + 500000
WHERE id_cuenta = 1;
DELETE FROM transacciones WHERE id_transaccion = 99;
Regla clave: El orden de inserción es estricto: debes cargar tablas fuertes antes de sus hijas.
3. DQL (Consulta / Lectura) Análisis / Reportes

Extrae, cruza y resume información

Es de solo lectura: no altera ni borra información. Combina tablas mediante JOIN, filtra y agrupa.

// Comando principal: SELECT
SELECT s.nombre, COUNT(e.id_empleado)
FROM sucursales s
LEFT JOIN empleados e ON s.id_sucursal = e.id_sucursal
GROUP BY s.nombre;
Regla clave: Es la base del examen práctico y de las 19 preguntas del laboratorio.

1. Operadores en WHERE

Sacados de Clase 6 y Talleres Biblioteca / Polideportivo

  • =, <>, >, <, >=, <= Comparar números o fechas. Ej: WHERE saldo > 5000000
  • AND / OR / IN Combinar condiciones. Ej: WHERE tipo IN ('Premium', 'VIP') AND edad > 20
  • LIKE '%texto%' Buscar texto parcial. Ej: WHERE correo LIKE '%@gmail.com' o nombre LIKE 'L%'
  • IS NULL / IS NOT NULL Préstamos activos: WHERE fecha_devolucion IS NULL

2. Funciones de Agregación

Calculan un resumen sobre muchas filas (Clase 6, Diap. 14)

  • COUNT(*) / COUNT(col) Cuenta cuántas filas hay. Ej: SELECT COUNT(*) FROM clientes;
  • SUM(columna) Suma valores numéricos. Ej: SUM(monto) por tipo de transacción.
  • AVG(columna) Calcula el promedio. Ej: AVG(salario) de empleados.
  • MIN(col) / MAX(col) El menor o mayor valor. Ej: MIN(anio_publicacion) (libro más antiguo).

3. Subconsultas en WHERE

¡Aparecen en las preguntas 15 a 19 del Lab del Banco!

Mayor al promedio (Pregunta 16): SELECT * FROM cuentas
WHERE saldo > (SELECT AVG(saldo) FROM cuentas);
El valor máximo/mínimo (Pregunta 17 y 19): SELECT * FROM empleados
WHERE salario = (SELECT MAX(salario) FROM empleados);
Los que NO están en otra tabla (Pregunta 18): SELECT * FROM clientes
WHERE id_cliente NOT IN (SELECT id_cliente FROM prestamos);

Para evitar errores de tipo ERROR: relation "..." does not exist o violación de llave foránea (foreign key constraint), las tablas deben crearse e insertarse en estricto orden jerárquico:

Nivel 1 • Tablas Fuertes Sin FK previa

1. sucursales, clientes, tipos_cuenta

No dependen de nadie. Contienen las entidades maestras que prestarán sus llaves primarias (id_sucursal, id_cliente, id_tipo).

Nivel 2 • Dependientes Directas FK Nivel 1

2. empleados, cuentas, prestamos

empleados apunta a sucursales. cuentas apunta a clientes y tipos_cuenta. prestamos apunta a clientes.

Nivel 3 • Dependiente Secundaria FK a Cuentas

3. transacciones

Cada transacción requiere obligatoriamente que la cuenta bancaria ya exista (id_cuenta FK → cuentas). Debe crearse y poblarse al final.

Sentencias DDL (CREATE TABLE) de las 7 Tablas

Definición formal respetando los tipos de datos en PostgreSQL (SERIAL PRIMARY KEY, NUMERIC(12,2) para dinero, DATE, TIMESTAMP y restricciones de integridad FOREIGN KEY): 

-- =========================================================================
-- TABLA 1: sucursales (Fuerte)
-- =========================================================================
CREATE TABLE sucursales (
    id_sucursal SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    ciudad VARCHAR(50) NOT NULL,
    direccion VARCHAR(150) NOT NULL
);

-- =========================================================================
-- TABLA 2: empleados (Depende de sucursales)
-- =========================================================================
CREATE TABLE empleados (
    id_empleado SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    cargo VARCHAR(50) NOT NULL,
    salario NUMERIC(12,2) NOT NULL,
    id_sucursal INT NOT NULL,
    CONSTRAINT fk_empleados_sucursal FOREIGN KEY (id_sucursal) 
        REFERENCES sucursales(id_sucursal) ON DELETE RESTRICT ON UPDATE CASCADE
);

-- =========================================================================
-- TABLA 3: clientes (Fuerte)
-- =========================================================================
CREATE TABLE clientes (
    id_cliente SERIAL PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    apellido VARCHAR(50) NOT NULL,
    telefono VARCHAR(20),
    correo VARCHAR(100) UNIQUE,
    ciudad VARCHAR(50) NOT NULL
);

-- =========================================================================
-- TABLA 4: tipos_cuenta (Fuerte)
-- =========================================================================
CREATE TABLE tipos_cuenta (
    id_tipo SERIAL PRIMARY KEY,
    descripcion VARCHAR(50) NOT NULL
);

-- =========================================================================
-- TABLA 5: cuentas (Depende de clientes y tipos_cuenta)
-- =========================================================================
CREATE TABLE cuentas (
    id_cuenta SERIAL PRIMARY KEY,
    numero_cuenta VARCHAR(20) UNIQUE NOT NULL,
    saldo NUMERIC(12,2) NOT NULL DEFAULT 0.00,
    fecha_apertura DATE NOT NULL,
    estado VARCHAR(20) NOT NULL DEFAULT 'Activa',
    id_cliente INT NOT NULL,
    id_tipo INT NOT NULL,
    CONSTRAINT fk_cuentas_cliente FOREIGN KEY (id_cliente) 
        REFERENCES clientes(id_cliente) ON DELETE RESTRICT ON UPDATE CASCADE,
    CONSTRAINT fk_cuentas_tipo FOREIGN KEY (id_tipo) 
        REFERENCES tipos_cuenta(id_tipo) ON DELETE RESTRICT ON UPDATE CASCADE
);

-- =========================================================================
-- TABLA 6: transacciones (Depende de cuentas)
-- =========================================================================
CREATE TABLE transacciones (
    id_transaccion SERIAL PRIMARY KEY,
    tipo VARCHAR(30) NOT NULL,
    monto NUMERIC(12,2) NOT NULL,
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    id_cuenta INT NOT NULL,
    CONSTRAINT fk_transacciones_cuenta FOREIGN KEY (id_cuenta) 
        REFERENCES cuentas(id_cuenta) ON DELETE CASCADE ON UPDATE CASCADE
);

-- =========================================================================
-- TABLA 7: prestamos (Depende de clientes)
-- =========================================================================
CREATE TABLE prestamos (
    id_prestamo SERIAL PRIMARY KEY,
    monto NUMERIC(12,2) NOT NULL,
    tasa_interes NUMERIC(5,2) NOT NULL,
    fecha_inicio DATE NOT NULL,
    cuotas INT NOT NULL,
    id_cliente INT NOT NULL,
    CONSTRAINT fk_prestamos_cliente FOREIGN KEY (id_cliente) 
        REFERENCES clientes(id_cliente) ON DELETE RESTRICT ON UPDATE CASCADE
);

Puedes pegar todo este bloque en el Query Tool de pgAdmin o ejecutarlo desde la terminal con: psql -U postgres -d bancodb -f setup_bancodb.sql. Incluye borrado preventivo seguro (DROP TABLE IF EXISTS ... CASCADE). 

-- =============================================================================
-- LABORATORIO FINAL BASES DE DATOS - BANCODB
-- Script Maestro Oficial DDL + DML Completo
-- =============================================================================

-- 1. Limpieza preventiva
DROP TABLE IF EXISTS transacciones CASCADE;
DROP TABLE IF EXISTS prestamos CASCADE;
DROP TABLE IF EXISTS cuentas CASCADE;
DROP TABLE IF EXISTS empleados CASCADE;
DROP TABLE IF EXISTS tipos_cuenta CASCADE;
DROP TABLE IF EXISTS clientes CASCADE;
DROP TABLE IF EXISTS sucursales CASCADE;

-- 2. DDL - Creación de Tablas (Orden de Dependencias)
CREATE TABLE sucursales (
    id_sucursal SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    ciudad VARCHAR(50) NOT NULL,
    direccion VARCHAR(150) NOT NULL

CREATE TABLE empleados (

    CONSTRAINT fk_empleados_sucursal FOREIGN KEY (id_sucursal) 
        REFERENCES sucursales(id_sucursal) ON DELETE RESTRICT ON UPDATE CASCADE
);

CREATE TABLE clientes (
    id_cliente SERIAL PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    apellido VARCHAR(50) NOT NULL,
    telefono VARCHAR(20),
    correo VARCHAR(100) UNIQUE,
    ciudad VARCHAR(50) NOT NULL
);

CREATE TABLE tipos_cuenta (
    id_tipo SERIAL PRIMARY KEY,
    descripcion VARCHAR(50) NOT NULL
);

CREATE TABLE cuentas (
    id_cuenta SERIAL PRIMARY KEY,
    numero_cuenta VARCHAR(20) UNIQUE NOT NULL,
    saldo NUMERIC(12,2) NOT NULL DEFAULT 0.00,
    fecha_apertura DATE NOT NULL,
    estado VARCHAR(20) NOT NULL DEFAULT 'Activa',
    id_cliente INT NOT NULL,
    id_tipo INT NOT NULL,
    CONSTRAINT fk_cuentas_cliente FOREIGN KEY (id_cliente)

    CONSTRAINT fk_cuentas_tipo FOREIGN KEY (id_tipo)

CREATE TABLE transacciones (
    id_transaccion SERIAL PRIMARY KEY,

    monto NUMERIC(12,2) NOT NULL,
    fecha TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    id_cuenta INT NOT NULL,
    CONSTRAINT fk_transacciones_cuenta FOREIGN KEY (id_cuenta) 
        REFERENCES cuentas(id_cuenta) ON DELETE CASCADE ON UPDATE CASCADE
);

CREATE TABLE prestamos (
    id_prestamo SERIAL PRIMARY KEY,
    monto NUMERIC(12,2) NOT NULL,
    tasa_interes NUMERIC(5,2) NOT NULL,
    fecha_inicio DATE NOT NULL,
    cuotas INT NOT NULL,
    id_cliente INT NOT NULL,
    CONSTRAINT fk_prestamos_cliente FOREIGN KEY (id_cliente) 
        REFERENCES clientes(id_cliente) ON DELETE RESTRICT ON UPDATE CASCADE
);

Checklist para el Informe de Resultados Paso a Paso

"Entrega un informe detallado con los resultados"

Sigue esta lista de verificación interactiva para estructurar tu documento de entrega (Word/PDF). Marca cada casilla a medida que captures tus evidencias:

Solucionario de las 19 Consultas para tu Informe Datos exactos esperados
1. Clientes ordenados por ciudad (ORDER BY) ORDER BY ciudad
SELECT nombre, apellido, ciudad FROM clientes ORDER BY ciudad;

Resultado devuelto: 5 filas. Bogotá (Camila, Juan), Cali (María), Medellín (Pedro), Pasto (Laura).

2. Cuentas con saldo superior a 5 millones WHERE saldo > 5000000
SELECT * FROM cuentas WHERE saldo > 5000000;

Resultado devuelto: 2 filas (Cuenta 20003 con $9,500,000 y 20005 con $15,000,000).

3. Total de clientes registrados COUNT(*)
SELECT COUNT(*) AS total_clientes FROM clientes;

Resultado devuelto: 1 fila (total_clientes = 5).

4. Salario promedio de los empleados AVG(salario)
SELECT AVG(salario) AS salario_promedio FROM empleados;

Resultado devuelto: 1 fila (salario_promedio = 4750000.00).

5. Clientes junto con su número de cuenta (JOIN) JOIN cuentas ON c.id = cu.id_cliente
SELECT c.nombre, c.apellido, cu.numero_cuenta FROM clientes c JOIN cuentas cu ON c.id_cliente = cu.id_cliente;

Resultado devuelto: 5 filas (Juan-20001, María-20002, Pedro-20003, Laura-20004, Camila-20005).

6. Clientes y el tipo de cuenta que poseen (JOIN 3 tablas) clientes + cuentas + tipos_cuenta
SELECT c.nombre, c.apellido, tc.descripcion AS tipo_cuenta FROM clientes c JOIN cuentas cu ON c.id_cliente = cu.id_cliente JOIN tipos_cuenta tc ON cu.id_tipo = tc.id_tipo;

Resultado devuelto: 5 filas. Juan (Ahorros), María (Corriente), Pedro (Ahorros), Laura (Corriente), Camila (Ahorros).

7. Empleados y la sucursal donde trabajan (JOIN) empleados + sucursales
SELECT e.nombre, e.cargo, s.nombre AS sucursal FROM empleados e JOIN sucursales s ON e.id_sucursal = s.id_sucursal;

Resultado devuelto: 4 empleados vinculados a Sucursal Centro (2), Sucursal Norte (1) y Sucursal Sur (1).

8. Clientes con préstamos y valor del préstamo (JOIN) clientes + prestamos
SELECT c.nombre, c.apellido, p.monto AS valor_prestamo FROM clientes c JOIN prestamos p ON c.id_cliente = p.id_cliente;

Resultado devuelto: 3 filas (Juan $10M, María $5M, Pedro $15M).

9. Todas las transacciones por cada cliente (JOIN 3 tablas) clientes + cuentas + transacciones
SELECT c.nombre, c.apellido, t.id_transaccion, t.tipo, t.monto FROM clientes c JOIN cuentas cu ON c.id_cliente = cu.id_cliente JOIN transacciones t ON cu.id_cuenta = t.id_cuenta;

Resultado devuelto: 6 filas detallando cada depósito, retiro o transferencia.

10. Cuántos clientes existen por ciudad (GROUP BY) GROUP BY ciudad
SELECT ciudad, COUNT(*) AS total_clientes FROM clientes GROUP BY ciudad;

Paso 5 • Protocolo Anti-Bloqueo

Qué hacer exactamente cuando pases al puesto del profesor

Cuando el profesor está mirando tu pantalla es normal ponerse nervioso. Sigue estos 5 pasos mecánicos en orden y nunca te quedarás en blanco.

1

No escribas SQL todavía: mira las tablas

Identifica en el diagrama o gestor qué tablas tienen los datos que te piden. Si te piden datos de dos tablas que no se tocan directamente (ej. estudiantes y cursos), busca la tabla intermedia que tiene las dos llaves foráneas (inscripciones).

2

Traduce la frase del profesor a tipo de JOIN

  • • "Muestra X con su Y" → INNER JOIN
  • • "Muestra TODOS los X, tengan o no Y" → LEFT JOIN (poniendo X en el FROM)
  • • "Muestra los X que NO tienen Y" → LEFT JOIN + WHERE Y.id IS NULL
  • • "Muestra todos de ambas tablas" → FULL OUTER JOIN
3

Escribe primero el FROM y los JOIN

Pon SELECT * temporalmente, arma tu FROM tabla1 t1 y encadena tus JOIN tabla2 t2 ON t1.pk = t2.fk. Ejecuta eso primero para comprobar que no haya errores de sintaxis.

4

Reemplaza el * por las columnas exactas

Cambia el * por las columnas que pidió el enunciado usando siempre el alias adelante (ej: e.nombre, c.nombre_curso). Revisa que no falte ninguna coma entre columnas ni sobre una antes del FROM.

🚨 Los 4 errores que más hacen perder puntos frente al profesor

1. Olvidar el ON: Todo INNER/LEFT/RIGHT/FULL JOIN exige un ON tabla1.llave = tabla2.llave. Sin el ON da error de sintaxis.
2. Igualar columnas que no son llaves: Nunca hagas ON e.nombre = c.nombre_curso. Siempre iguala PK con FK (e.id_estudiante = i.id_estudiante).
3. Columna ambigua: Si escribes SELECT id_estudiante sin poner e.id_estudiante, SQL dirá "Column 'id_estudiante' is ambiguous".
4. Usar INNER JOIN cuando piden "TODOS": Si te dicen "todos los cursos, incluso sin inscritos" y usas INNER JOIN, los cursos vacíos desaparecerán.
