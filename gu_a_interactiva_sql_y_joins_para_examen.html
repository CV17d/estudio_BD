SELECT s.nombre AS sucursal, COUNT(e.id_empleado) AS total_emp
FROM sucursales s
LEFT JOIN empleados e ON s.id_sucursal = e.id_sucursal
WHERE e.salario > 2000000
GROUP BY s.nombre
HAVING COUNT(e.id_empleado) >= 1
ORDER BY total_emp DESC;

DDL vs. DML de Escritura vs. DQL (Mapeado a bancodb)

Distingue el rol exacto de cada familia de comandos evaluadas por el profesor en el Laboratorio Final:

1. DDL (Definición) Estructura / Catálogo

Define contenedores y restricciones

Modifica el catálogo de la BD: crea o altera bases de datos, tablas, tipos, llaves primarias (PK) y foráneas (FK).

// Comandos: CREATE, ALTER, DROP
CREATE DATABASE bancodb;
CREATE TABLE sucursales (
id_sucursal SERIAL PRIMARY KEY,
nombre VARCHAR(100) NOT NULL
);
ALTER TABLE prestamos ADD estado VARCHAR(20);
Regla clave: No manipula filas individuales, solo el plano o molde de almacenamiento.
2. DML (Manipulación) Datos / Filas

Inserta, actualiza o borra registros

Alimenta y mantiene los registros vivos respetando las restricciones de integridad referencial.

// Comandos: INSERT, UPDATE, DELETE
INSERT INTO sucursales(nombre, ciudad)
VALUES ('Sucursal Centro', 'Bogotá');
UPDATE cuentas
SET saldo = saldo + 500000
WHERE id_cuenta = 1;
DELETE FROM transacciones WHERE id_transaccion = 99;
Regla clave: El orden de inserción es estricto: debes cargar tablas fuertes antes de sus hijas.
3. DQL (Consulta / Lectura) Análisis / Reportes

Extrae, cruza y resume información

Es de solo lectura: no altera ni borra información. Combina tablas mediante JOIN, filtra y agrupa.

// Comando principal: SELECT
SELECT s.nombre, COUNT(e.id_empleado)
FROM sucursales s
LEFT JOIN empleados e ON s.id_sucursal = e.id_sucursal
GROUP BY s.nombre;
Regla clave: Es la base del examen práctico y de las 19 preguntas del laboratorio.

1. Operadores en WHERE

Sacados de Clase 6 y Talleres Biblioteca / Polideportivo

  • =, <>, >, <, >=, <= Comparar números o fechas. Ej: WHERE saldo > 5000000
  • AND / OR / IN Combinar condiciones. Ej: WHERE tipo IN ('Premium', 'VIP') AND edad > 20
  • LIKE '%texto%' Buscar texto parcial. Ej: WHERE correo LIKE '%@gmail.com' o nombre LIKE 'L%'
  • IS NULL / IS NOT NULL Préstamos activos: WHERE fecha_devolucion IS NULL

2. Funciones de Agregación

Calculan un resumen sobre muchas filas (Clase 6, Diap. 14)

  • COUNT(*) / COUNT(col) Cuenta cuántas filas hay. Ej: SELECT COUNT(*) FROM clientes;
  • SUM(columna) Suma valores numéricos. Ej: SUM(monto) por tipo de transacción.
  • AVG(columna) Calcula el promedio. Ej: AVG(salario) de empleados.
  • MIN(col) / MAX(col) El menor o mayor valor. Ej: MIN(anio_publicacion) (libro más antiguo).

3. Subconsultas en WHERE

¡Aparecen en las preguntas 15 a 19 del Lab del Banco!

Mayor al promedio (Pregunta 16): SELECT * FROM cuentas
WHERE saldo > (SELECT AVG(saldo) FROM cuentas);
El valor máximo/mínimo (Pregunta 17 y 19): SELECT * FROM empleados
WHERE salario = (SELECT MAX(salario) FROM empleados);
Los que NO están en otra tabla (Pregunta 18): SELECT * FROM clientes
WHERE id_cliente NOT IN (SELECT id_cliente FROM prestamos);

Crear Tablas e Insertar Datos (Paso a Paso)

Aprende sin enredos la base de SQL: cómo crear tu primera tabla con CREATE TABLE, cómo vincular dos tablas mediante FOREIGN KEY, cómo poblarla con INSERT INTO y cómo hacer modificaciones puntuales con UPDATE y DELETE.

1
DDL Básico

Cómo Crear una Tabla Simple (CREATE TABLE)

Toda tabla en SQL se define indicando su nombre y, entre paréntesis, sus columnas separadas por comas. Cada columna sigue la estructura: nombre_columna TIPO_DATO [RESTRICCIÓN].

1. INT / SERIAL Para números enteros. SERIAL se incrementa solo (1, 2, 3...) ideal para IDs.
2. VARCHAR(n) Para textos con longitud máxima. Ej: VARCHAR(50) para nombres.
3. PRIMARY KEY & NOT NULL PRIMARY KEY identifica de forma única la fila. NOT NULL prohíbe valores vacíos. 
-- Ejemplo de una sola tabla independiente (Tabla Fuerte)
CREATE TABLE departamentos (
    id_departamento INT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    presupuesto NUMERIC(12,2)
);
💡
¿Qué significa cada línea?
• id_departamento INT PRIMARY KEY: Identificador numérico único para cada departamento.
• nombre VARCHAR(50) NOT NULL: El nombre no puede superar los 50 caracteres y es obligatorio.
• presupuesto NUMERIC(12,2): Dinero con hasta 12 dígitos y 2 decimales (opcional).
2
Relación de Tablas

Cómo Enlazar Dos Tablas con FOREIGN KEY

Para que una tabla apunte a otra, creas una columna hija y la declaras como FOREIGN KEY hacia la PRIMARY KEY de la tabla padre. Esto garantiza que no existan datos huérfanos.

1. Tabla Padre (Fuerte) departamentos

Debe crearse primero para poder ser referenciada.

🔑 id_departamento (PK)
2. Tabla Hija (Dependiente) empleados

Contiene la columna que viaja hacia el padre.

🔗 id_departamento (FK) → departamentos 
-- Tabla 2: empleados (depende de departamentos)
CREATE TABLE empleados (
    id_empleado INT PRIMARY KEY,
    nombre VARCHAR(60) NOT NULL,
    salario NUMERIC(10,2) NOT NULL,
    id_departamento INT,
    FOREIGN KEY (id_departamento) REFERENCES departamentos(id_departamento)
);
⚠️
Regla de Oro en Examen: ¡No puedes crear empleados antes que departamentos! Si lo intentas, PostgreSQL lanzará un error indicando que la relación no existe.
3
DML de Escritura

Insertar (INSERT INTO), Modificar (UPDATE) y Borrar (DELETE)

1. INSERT INTO

Agregar registros

Inserta una fila o múltiples filas separadas por comas:

-- 1 fila
INSERT INTO departamentos 
VALUES (1, 'Ventas', 4000000);

-- Múltiples filas
INSERT INTO departamentos 
VALUES 
  (2, 'Tecnología', 8000000),
  (3, 'Finanzas', 6000000);
2. UPDATE ... SET

Modificar registros

Actualiza un dato existente. ¡Siempre usa WHERE!

-- Subir el salario a un empleado
UPDATE empleados 
SET salario = 3500000 
WHERE id_empleado = 101;
Peligro: Si no pones WHERE, ¡le cambias el salario a todos!
3. DELETE FROM

Eliminar registros

Borra filas que cumplan una condición con WHERE:

-- Eliminar un empleado puntual
DELETE FROM empleados 
WHERE id_empleado = 102;
Peligro: Sin WHERE vacías toda la tabla. 
-- 1. Insertar departamentos (Tabla Padre)
INSERT INTO departamentos (id_departamento, nombre, presupuesto) VALUES 
(1, 'Tecnología', 8000000),
(2, 'Ventas', 4000000),
(3, 'Finanzas', 6000000);

-- 2. Insertar empleados (Tabla Hija referenciando id_departamento)
INSERT INTO empleados (id_empleado, nombre, salario, id_departamento) VALUES 
(101, 'Ana Torres', 3500000, 1),
(102, 'Carlos Ruiz', 2800000, 2);

-- 3. Modificar un salario puntual
UPDATE empleados SET salario = 3800000 WHERE id_empleado = 101;

-- 4. Eliminar un empleado puntual
DELETE FROM empleados WHERE id_empleado = 102;

El más usado

Busca coincidencias exactas entre ambas tablas usando la columna en común (id_estudiante). Si un estudiante no está inscrito, no aparece. Si una inscripción no tiene estudiante válido, tampoco aparece.

Paso siguiente • Cruce + Agrupación + Filtros de Grupo

Paso siguiente: Combinar JOIN + GROUP BY + HAVING + ORDER BY

En los exámenes más exigentes, el profesor no te pedirá un simple JOIN plano: te pedirá unir tablas, agruparlas por cliente o estudiante, filtrar únicamente los grupos que cumplan una condición estadística y ordenarlos.

1 El Orden Estricto de Escritura vs. Ejecución

⚠️ ¡Regla de Oro para Examen!

SQL debe escribirse obligatoriamente en esta secuencia exacta o el motor lanzará error de sintaxis:

1. SELECT → 2. FROM → 3. JOIN ... ON → 4. WHERE → 5. GROUP BY → 6. HAVING → 7. ORDER BY

Dato de ejecución interna: El motor de PostgreSQL ejecuta internamente primero el FROM / JOIN para construir la tabla cruzada, filtra filas con WHERE, agrupa con GROUP BY, descarta grupos con HAVING, proyecta las columnas con SELECT y finalmente ordena con ORDER BY.

2

Diferencia Clave: WHERE vs. HAVING

WHERE (Filtra filas individuales)

Actúa ANTES de agrupar. Evalúa columna por columna. ¡NUNCA pongas COUNT(), SUM(), AVG() en WHERE!

WHERE cu.saldo > 1000000
HAVING (Filtra grupos calculados)

Actúa DESPUÉS de agrupar. Solo se usa con GROUP BY para evaluar resultados de funciones de agregación.

HAVING COUNT(cu.id_cuenta) > 1
3

ORDER BY: Ordenamiento Final

Determina cómo se presentan las filas finales al usuario o al profesor:

ASC (Ascendente) De menor a mayor (A → Z, 1 → 9). Es el valor por defecto si no escribes nada.
1 → 100
DESC (Descendente) De mayor a menor (Z → A, 100 → 1). Esencial para "los saldos más altos" o "más inscritos".
100 → 1
Tip: Puedes ordenar por una columna calculada usando su alias asignado en el SELECT (ej: ORDER BY saldo_total DESC).

                    Paso 5 • Protocolo Anti-Bloqueo
                
                
Qué hacer exactamente cuando pases al puesto del profesor

                
Cuando el profesor está mirando tu pantalla es normal ponerse nervioso. Sigue estos 5 pasos mecánicos en orden y nunca te quedarás en blanco.


                

                    
                    

                        

                            1
                            
No escribas SQL todavía: mira las tablas

                        

                        

                            Identifica en el diagrama o gestor qué tablas tienen los datos que te piden. Si te piden datos de dos tablas que no se tocan directamente (ej. estudiantes y cursos), busca la tabla intermedia que tiene las dos llaves foráneas (inscripciones).
                        

                    


                    
                    

                        

                            2
                            
Traduce la frase del profesor a tipo de JOIN

                        

                        
    
                            
  • • "Muestra X con su Y" → INNER JOIN
    • 
                            
  • • "Muestra TODOS los X, tengan o no Y" → LEFT JOIN (poniendo X en el FROM)
    • 
                            
  • • "Muestra los X que NO tienen Y" → LEFT JOIN + WHERE Y.id IS NULL
    • 
                            
  • • "Muestra todos de ambas tablas" → FULL OUTER JOIN
    • 
                        

                    


                    
                    

                        

                            3
                            
Escribe primero el FROM y los JOIN

                        

                        

                            Pon SELECT * temporalmente, arma tu FROM tabla1 t1 y encadena tus JOIN tabla2 t2 ON t1.pk = t2.fk. Ejecuta eso primero para comprobar que no haya errores de sintaxis.
                        

                    


                    
                    

                        

                            4
                            
Reemplaza el * por las columnas exactas

                        

                        

                            Cambia el * por las columnas que pidió el enunciado usando siempre el alias adelante (ej: e.nombre, c.nombre_curso). Revisa que no falte ninguna coma entre columnas ni sobre una antes del FROM.
                        

                    

                


                
                

                    

                        🚨 Los 4 errores que más hacen perder puntos frente al profesor
                    

                    

                        

                            1. Olvidar el ON: Todo INNER/LEFT/RIGHT/FULL JOIN exige un ON tabla1.llave = tabla2.llave. Sin el ON da error de sintaxis.
                        

                        

                            2. Igualar columnas que no son llaves: Nunca hagas ON e.nombre = c.nombre_curso. Siempre iguala PK con FK (e.id_estudiante = i.id_estudiante).
                        

                        

                            3. Columna ambigua: Si escribes SELECT id_estudiante sin poner e.id_estudiante, SQL dirá "Column 'id_estudiante' is ambiguous".
                        

                        

                            4. Usar INNER JOIN cuando piden "TODOS": Si te dicen "todos los cursos, incluso sin inscritos" y usas INNER JOIN, los cursos vacíos desaparecerán.
